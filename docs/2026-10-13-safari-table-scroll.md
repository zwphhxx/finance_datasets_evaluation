# Safari 390px 表格横向阅读验收

本次仅调整展示：共同样本比较的模型列恢复按内容确定宽度，移除移动端
`stDataFrame` 外层重复的横向滚动设置，由 Streamlit 原生表格管理滚动。
评分计算、数据筛选、历史记录与证据口径均未修改。

## 实测范围

- macOS Safari 26.5.2 原生响应式设计模式，390 × 844 CSS px。
- 使用已有历史结果的本地只读回放，模型调用与历史写入被禁止。
- 比较表默认左端完整显示五个模型及服务配置，无需先手动 Autosize。
- 实际拖动原生滚动条至右端，五个均分完整可读；拖回左端可继续核对名称。
- Safari 只读 DOM 检查：视口宽度 390，文档宽度 390；比较表原生滚动区
  宽度 351、内容宽度 422，实际滚动位置达到 71，等于最大横向位移。
- 修复前同时存在外层和原生滚动条；修复后仅保留原生滚动条。

## 自动验证与边界

两个回归测试先复现失败，再通过：长模型身份文本与评分原值保持完整，
模型列不强制固定宽度，移动端不新增第二个滚动容器。
全量 pytest：867 passed、7 skipped；Ruff 通过；数据集校验 20 项通过。
跳过项为未配置的 PostgreSQL 集成测试及需显式开启的旧浏览器测试。

本次属于桌面 Safari 的移动尺寸验收，不代表真实 iPhone 触摸手势验收。
截图与包含历史回答的验收材料保存在忽略的 `docs/ui/safari/`，不上传公开仓库。
