# 减法 UI 重构实施计划

目标：三个公开页面、一个管理入口；不新增指标、图表或评测能力。

公开路由沿用 conclusions（评测结果）、新增 review（整合既有案例审阅）、沿用 case_study（评测方法）。管理保留 test_run 和 samples 路由。旧 URL 继续有效，默认进入 conclusions。

- [x] 添加交互回归测试：三个公开入口、结果到具体案例、原始理由与缺失证据提示、刷新保持案例选择、默认阅读不触发 provider。
- [x] navigation.py/page_config.py：三个公开按钮及管理 popover；路由和案例参数随 URL 保持。
- [x] conclusions.py：集中比较、运行失败范围与原有历史评分观察；移除内联案例和管理表单；维度和技术信息按需展开。
- [x] review.py：统一案例与模型批次选择，复用完整评分详情；只读取运行时任务、Gold、维度，缺失时明确提示。全部记录包含原有证据弹窗能力。
- [x] case_study.py：仅方法、数据范围、研究边界、源码；样本数量动态读取。
- [x] management.py/samples.py/test_run.py：管理入口下保留样本 CRUD、评分导入导出、快照回放、自测和恢复操作；完成运行后可直接进入结果。
- [x] trust_details.py/responsive.py：去掉三重卡片边框，沿用两栏和移动堆叠；技术核查避免嵌套 expander。
- [x] 更新被明确新信息架构替代的旧 UI 合同；执行全量 pytest、Ruff、数据校验。
- [x] 用已有真实历史只读捕获，在 1440、768、390px 截图，核对首页→案例→评分证据、刷新和管理入口；复核源文件与历史数据库指纹。

安全边界：本地可审阅重构，不触发付费 API，不修改历史记录，不向公开仓库发布历史截图或快照。视觉截图仅存放已忽略的 docs/ui/ 目录。
