# 精品咨询报告视觉升级设计

日期：2026-08-13

状态：待用户书面审核

适用项目：财务/法律/投行场景大模型对比评测

## 1. 目标与边界

将现有 Streamlit 项目从通用管理后台式界面升级为“精品咨询报告”风格，使面试官在首次打开时感受到克制、可信、专业和清晰的决策层交付品质。

本次升级不改变：

- 任何现有项目文案及其表述；
- 样本、模型回答、评分和评测结论的数据口径；
- 评分模型、提示词、评分逻辑及 Token 调用条件；
- PostgreSQL/Supabase 增量持久化语义；
- 四个主导航页面及其业务流程；
- Streamlit 平台必要组件和平台标识。

本次升级覆盖视觉系统、页面信息层级、通用组件、响应式布局、交互反馈和数据库异常时的快速失败体验。
如结构调整需要新增短标签，只能复用项目已有业务术语；不得新增叙事性、营销性或结论性文案。

## 2. 已确认设计方向

采用 **B2：合伙人汇报式、均衡信息密度**。

- 首页具有正式咨询交付材料的报告感；
- 样本库和发起评测页保持实际操作效率；
- 桌面端不追求夸张留白，手机端不因视觉表达增加无意义滚动；
- 不采用大面积渐变、玻璃拟态、强阴影、装饰性图标或分散动效。

字体采用 **T2：标题衬线＋正文无衬线**。

- 首页主标题、页面关键结论使用中文衬线字体；
- 正文、模型回答、表格、数据、标签和按钮使用系统无衬线字体；
- 优先使用系统字体栈，不依赖外部字体服务，避免增加首屏延迟和网络不稳定性。

## 3. 视觉系统

### 3.1 色彩

| 角色 | 色值 | 用途 |
|---|---:|---|
| 报告纸张 | `#F7F5F0` | 全局背景 |
| 主表面 | `#FFFFFF` | 表格、详情和必要交互表面 |
| 深墨 | `#252621` | 主文字、主按钮、关键数据 |
| 石灰灰 | `#6F6B62` | 次级说明、元数据、辅助标签 |
| 暖灰线 | `#D9D4C9` | 分隔线、输入框和低强调边界 |
| 金棕 | `#9A7435` | 当前定位、选中状态、关键结论线 |

金棕是唯一强调色，只用于定位、选中和关键结论，不用于大面积按钮或背景。成功、警告和失败状态仍需可区分，但使用低饱和文字和细标记，不使用大面积高饱和色块。

### 3.2 字体与层级

- 衬线标题栈：`ui-serif, "Songti SC", "STSong", "Noto Serif CJK SC", serif`；
- 无衬线正文栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`；
- 首页标题承担报告封面角色；
- 页面标题、章节标题、正文、说明、数据和标签建立固定字号比例；
- 数据使用更紧凑字距，正文保持适合中文长回答的行高；
- 不通过大量超粗字重制造层级。

### 3.3 标志性元素

采用“结论先行线”作为唯一标志性设计：每个页面最重要的一句话左侧使用一条细金线，形成咨询报告中的 executive takeaway。每页最多使用一次，避免退化为普通装饰。

### 3.4 表面与边界

- 减少约三分之一不必要的边框和容器；
- 默认通过留白、字体和细分隔线建立层级；
- 仅详情、表格、输入控件和可交互区域使用明确表面；
- 圆角控制在轻微范围，不使用胶囊形大容器；
- 阴影仅用于弹窗或悬浮层，正文区域不使用卡片阴影。

## 4. 页面结构

### 4.1 全局导航

- 顶部导航表现为轻薄的报告目录栏；
- 左侧保留项目名称，右侧保留四个现有导航项；
- 当前页使用短金线和文字权重标识，不表现为填充按钮；
- 桌面端保持单行；手机端允许横向滚动且保留可触控尺寸。

### 4.2 项目说明

- 首屏采用“报告封面＋结论先行线＋事实数据”的结构；
- 使用现有项目名称和项目说明文案，不新增营销表述；
- 事实数据仅展示能从当前样本和评分配置稳定推导的内容；
- 下方依次展示项目定位、评测流程和数据边界；
- `01/02/03` 仅保留在具有明确阅读顺序的首页章节中。

### 4.3 样本库

- 按“标题区—筛选操作区—样本清单—样本详情”组织；
- 减少连续卡片，使用分隔线和留白划分信息；
- 状态标签保持低对比；
- 选中样本使用金棕细线或小范围定位标记；
- 编辑、导入和详情弹窗使用同一视觉规则。

### 4.4 发起评测

- 按现有真实流程组织为“评测配置—模型回答—AI 评分”；
- 当前步骤和运行状态具有最高操作权重；
- 已完成步骤降低视觉权重，但回答与评分仍可随时查看；
- 模型回答与评分详情优先展示摘要，需要时展开全文；
- 主操作保持深墨实底，次操作使用白底细边框。

### 4.5 评测结论

- 首屏先展示现有数据能够支持的核心判断；
- 随后展示模型对比、评分依据、主要问题和使用边界；
- 图表、表格和说明按“结论—证据—边界”顺序组织；
- 不引入脱离当前样本范围的排名或泛化表达。

## 5. 响应式设计

### 5.1 桌面端

- 内容最大宽度保持适合报告阅读，不无限拉宽；
- 首页可使用有限的双栏内容组织；
- 操作页面以清晰纵向流程为主，不构造复杂仪表盘网格。

### 5.2 平板端

- 导航和操作按钮保持可见；
- 双栏内容在空间不足时转为单栏；
- 表格允许局部横向滚动，页面本身不产生横向溢出。

### 5.3 手机端

- 导航横向滚动，当前页状态明确；
- 事实数据使用两列或按内容自然换行；
- 详情、回答和操作按阅读顺序单列展开；
- 触控目标不小于 44px；
- 底部主操作不得遮挡模型回答或评分内容；
- 在 390px 和 430px 视口进行重点验收。

## 6. 交互与状态

- 普通操作：白底、暖灰细边框；
- 主操作：深墨实底；
- 当前导航、选中行和关键结论：小范围金棕标识；
- 点击按钮后立即显示运行或加载反馈；
- 详情展开使用轻微过渡，同时支持 `prefers-reduced-motion`；
- 空状态明确说明下一步操作；
- 错误状态说明原因和处理方法，不只显示模糊的失败提示。

## 7. 数据库异常与性能体验

视觉升级同时处理已确认的 Supabase 阻塞体验，但不改变持久化语义：

- 数据库连接设置 3–5 秒的明确超时；
- 同一次 Streamlit 页面运行连接失败后不重复尝试；
- 数据库不可用时立即展示明确状态，不让按钮表现为无响应；
- 持久化不可用时禁止触发真实模型和裁判模型调用；
- 项目说明和静态样本内容仍可展示；
- 数据库恢复后重新建立连接并读取持久化结果；
- 不使用定时模型调用作为保活方式。

## 8. 组件范围

需要统一的共享组件包括：

- 顶部报告目录导航；
- 页面标题和结论先行线；
- 章节标题；
- 事实数据和运行状态；
- 主次按钮；
- 状态标签；
- 表格及选中行；
- 回答与评分详情；
- 表单和选择框；
- 弹窗；
- 空状态、加载状态和错误状态。

共享视觉规则集中维护，避免各页面通过高优先级 CSS 相互覆盖。Streamlit DOM 选择器应限制在已验证的稳定结构，并通过回归测试约束关键选择器。

## 9. 验收标准

### 9.1 视觉

- 四个页面使用同一视觉系统；
- 首屏具有明确的咨询报告气质；
- 页面主次清晰，主要操作和核心判断可快速识别；
- 不出现重复边框、无意义阴影或过度装饰；
- 原有文案表述不发生变化。

### 9.2 响应式

- 390px、430px、768px 和桌面宽度无页面级横向溢出；
- 导航、按钮、表格、弹窗和长回答可正常使用；
- 固定操作不遮挡正文；
- 文字不重叠，章节间距稳定。

### 9.3 功能与数据

- 现有页面导航、样本操作、评测、回答查看、评分和结论功能保持不变；
- 不改变评分模型及其结果口径；
- 不修改已有持久化数据；
- 数据库不可用时不触发真实模型调用；
- 数据库恢复后可读取历史回答和评分。

### 9.4 性能与异常

- 正常按钮点击立即出现可见反馈；
- 数据库不可用时在设定超时内结束等待并显示原因；
- 同次页面运行不发生重复失败连接；
- 视觉资源不依赖外部字体和大型图片。

## 10. 验证方法

- 共享组件和关键 CSS 规则的自动化契约测试；
- Streamlit 页面流程回归测试；
- 数据集完整性校验；
- 代码规范检查；
- 本地真实浏览器在桌面、平板、390px 和 430px 视口截图对比；
- 数据库正常、连接超时、项目暂停/失效三种状态的故障注入测试；
- 视觉验收不触发真实模型生成或裁判评分。
