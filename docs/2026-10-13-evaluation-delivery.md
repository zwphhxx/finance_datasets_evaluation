# 评测原型改进交付报告（2026-10-13）

## 实际交付

| 优先级 | 内容 | 验证及边界 |
| --- | --- | --- |
| P0 | 逐必须覆盖点/不可接受错误评价，四种状态、原文引文、错误类型、对应维度与理由；可展开证据及原始响应 | 引文逐字验证；不将文本存在等同于专业结论正确 |
| P0 | 严格整数/范围/完整理由/JSON结构校验，有限输出与服务错误重试，异常不进入正式结论 | 保留失败响应与尝试；成功AI评分仍直接形成结论 |
| P0 | FD-001/FD-002/CM-001确定性算式核查 | 仅适用于原材料哈希及明确单一数值表达；其他表达未知，不自动改权重 |
| P0 | 三个领域、九个人工固定回答的独立裁判自测及手动触发/导出 | 自测零自动调用、无重试、最多9次请求；离线测试不证明真实裁判可靠性 |
| P0 | 兼容版本组的共同有效任务比较、共同分母和不足解释 | 同模型不同端点评分独立；自身样本均分只用于单模型观察，不自动推荐最佳模型 |
| P0 | 计划/回答成功失败/评分成功失败/未完成分别统计 | 评分失败不归为回答失败，失败继续出现在运行记录中 |
| P0 | 完整快照导出、校验、只读回放、历史批次选择、无密钥空状态 | 快照显示来源、真实运行时间和配置；上传文件来源声明未经独立认证 |
| P0 | 保存并回放运行时题目、专业标准、Prompt与配置 | 数据库与快照均使用原始上下文；旧批次缺失材料明确标注，不拿当前题目替代 |
| P0 | 评分导入验证及证据字段保留 | 拒绝异常标记、小数、缺维度、不一致总分；结构化引文须匹配目标库原回答/Gold |
| P1 | 请求前/返回后独立保存全部回答及裁判尝试，重试用量、超时与中断分别观察 | 保留模型、服务商/端点、UTC请求时间、耗时、Token、状态、错误及序号；未知用量不填0 |
| P1 | 显式有效期价格配置和分别估算回答/裁判费用 | 不内置永久价格；缺用量/价格/尝试、未完成计划或混币种时不输出完整费用及每达标任务成本 |

## 主要文件

- `app/services/scorer.py`、`score_evidence.py`：结构化裁判协议、范围/引文校验、原始响应、固定公式与导入兼容。
- `app/persistence/schema.py`、`result_store.py`：可空字段的增量迁移、独立请求记录、事务保存与导入证据关联。
- `app/services/run_checkpoint.py`、`evaluation_workflow.py`、`eval_runner.py`、`request_audit.py`：保存运行时材料与Prompt，每次调用独立记录；已记录端点变化时停止恢复。
- `app/services/conclusions.py`、`comparison.py`、`conclusion_read_model.py`、`evidence_index.py`：保留端点评分、共同样本比较和原始证据投影。
- `app/services/snapshot.py`、`src/ui/conclusions_data.py`：完整只读快照及数据库历史上下文恢复、敏感字段过滤。
- `app/services/judge_selftest.py`、`judge_selftest_cases.json`：人工构造固定回答与已知错误检查，完全独立于正式评分表。
- `app/services/runtime_metrics.py`：重试累计、未知用量、价格有效期、币种及覆盖检查。
- `src/ui/conclusions.py`、`evaluation_results.py`、`history_view.py`、`trust_details.py`：沿用页面与视觉系统，补充展开详情、来源、运行统计、快照和自测入口。
- `README.md`、`docs/trustworthy_evaluation.md`：使用方式、结果来源、费用配置与验证边界。
- 新增9个针对性测试文件，并补充现有评分、存储、历史上下文、端点恢复和UI回归。旧测试中静默clamp的预期改为拒绝越界；有效评分Fixture补齐理由与整数维度，未削弱评分标准。

继续使用Python、Streamlit、现有Provider、SQLite/PostgreSQL ResultStore、增量事务及完整队列、数据/Prompt/配置哈希、五维100分评分口径、自动结论、输入白名单、正式/示例隔离、旧评分导入导出、现有证据索引与响应式样式。没有增加强制逐条复核门槛、RAG、Agent或其他无关功能。

## 兼容性与未完成项

1. 原有样本、数据文件、历史库及主页面保留。旧SQLite结构使用可空字段和新增表增量迁移，幂等迁移在临时旧结构数据库验证；没有DROP、清空或覆盖历史操作。本次没有对原本地库执行迁移；下次使用新版运行结果层时自动升级字段。
2. 旧记录没有的引文、原始响应、端点、运行时材料或请求尝试保持缺失。缺少版本/配置的历史记录可在原数据层读取，但不能伪装成可比实验；完整快照加载要求必要来源与配置齐备。
3. 严格评分输出可能使旧裁判输出被拒绝，并增加有限重试费用；评分维度和总分权重未改变。主页面裁判输出上限由2048增至3072 Token，以容纳逐要点证据。
4. 实际裁判识别专业错误、扣分及篇幅偏好尚未通过真实API验证；程序匹配引文不能验证推理语义。固定公式仅覆盖三个原始案例，非通用数值解析器。
5. PostgreSQL原生迁移/事务及真实浏览器移动端布局未在本次执行；SQLite与Streamlit AppTest通过不等于这些环境通过。已有移动样式复用，未进行UI大重构。
6. 快照做结构、关联、范围、引文和常见秘密/路径过滤，不提供第三方真实性认证，也不能识别所有业务敏感文本。
7. P2三个挑战变体未实施。只补充“缺失必要条件可说明无法确定部分”的提示边界，原13个任务和原标准未修改。

## 后续具体操作

1. 无密钥访客直接启动 `streamlit run app.py`，查看题库、说明及空状态；也可在结论页只读加载已有真实完整快照。
2. 如需形成公开实测成果，在已配置密钥的环境手动发起正式评测，再点击“导出完整评测快照”。检查脱敏后，将真实文件放到 `public/evaluation_snapshot.json`，访客可自动回放。当前不能发布虚构结果填充空状态。
3. 如需验证裁判，点击结论页“手动运行9次裁判自测（产生API费用）”。每次最多9个请求、每请求输出上限3072 Token、不重试；检查并导出独立结果。它不进入正式结论。
4. 如需费用观察，上传含服务商、模型、来源、币种、有效日期与每百万Token单价的价格JSON。原有历史未知用量不能靠补价格变成完整成本。
5. 需要进一步验证PostgreSQL时使用独立测试库设置 `TEST_DATABASE_URL`；真实浏览器回归按现有文档显式启用。不要把测试配置指向历史生产数据。
