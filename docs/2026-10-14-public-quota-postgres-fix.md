# PostgreSQL额度不足误报修复

用户在开始评测时收到「今日全站评测额度已不足」。只读检查线上数据库发现：三个新增额度表已建立，但每日预算和公开任务记录都是空的，历史运行仍为2批。并非任务额度已被实际占用。

根因是额度UPSERT使用 `CursorResult.rowcount == 1` 判断是否被限额条件接受。SQLAlchemy会关闭不返回结果的INSERT游标，而当前psycopg驱动关闭游标后rowcount从1变为-1；应用将未知行数误认为被限额拒绝，回滚额度预占，因此没有新增任务或模型调用。

只读SELECT验证了实际驱动的关闭行为。新增隔离回归通过连接代理模拟该行为，旧代码在第一笔合法预占时确实报相同错误。修复将每日及每对任务UPSERT改为 `RETURNING`，按是否实际返回一行判断；保留原子事务、并发上限及超额拒绝，未改变10任务/日、5请求/对及50请求/日的限制。

本次没有修改或重置线上额度、任务或原始历史，没有进行付费模型调用。线上发布核对只读取新版标识与页面，不点击开始按钮；因此生产模型生成及评分仍需要用户的明确操作才能验证。

修复发布标识：`public-limited-evaluation-20261014-v2`。原v1的界面验收记录保留在 `2026-10-14-public-limited-evaluation.md`。

本地验证：全量1017通过、7跳过，Ruff及diff检查通过；新增驱动行为回归先失败后通过。15个原始本地文件指纹未改变。测试未连接生产写库或模型服务。
