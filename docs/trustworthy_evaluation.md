# 评分证据、历史回放与费用观察

## 可复核评分与可靠性边界

五维权重保持为专业准确性 30、推理与场景适配 20、风险覆盖 20、依据可靠性 15、专业表达 15，总计 100 分。新评分对每个必须覆盖点和不可接受错误分别输出“满足、部分满足、未满足、无法判断”、原文引文、错误类型、对应维度和评分依据。不可接受错误条目的“满足”表示避免该错误。

程序逐字检查连续引文是否存在于对应回答中；**文本存在不代表专业判断正确或引文充分支持结论**。未覆盖或无法判断的要点可无引文，界面会明确标为无法验证。越界、小数、字段缺失、重复JSON字段、虚构引文等异常不进入正式结论，保留原始响应和失败原因。裁判服务错误及输出校验失败共享最多两次重试预算（最多三次请求）；鉴权等不可恢复错误不重试。被测回答遇特定超时/截断/Token上限错误最多重试一次，复用原有策略。

确定性数值核查目前覆盖原始 FD-001 的增长/比例、FD-002 的跌价和缺口、CM-001 的交易比例，使用固定算式并校验题目材料哈希。只识别明确标注且无歧义的数值；找不到表达标为未知，材料变化时停用固定规则。程序不擅自修改原有评分权重；核查结果同时提供给裁判和结果浏览。其他案例仍依赖裁判判断。

旧评分仍可读取，但没有的结构化证据、原始响应和请求用量不会补造。历史结论使用运行时保存的任务和专业标准；旧批次未保存原材料时会明确缺失，不拿当前题目替代历史。导入的新评分必须提供完整整数维度、合法范围及一致总分；带结构化证据的记录还须匹配目标数据库的原始回答及标准。

## 公平比较与运行统计

已有数据版本、数据哈希、Prompt哈希、生成和裁判配置检查继续使用。质量比较取兼容运行组中各模型/服务配置的**共同有效任务交集**，展示共同任务ID、数量和均分；不足两个比较对象或共同任务少于3条不给出优劣结论。这个阈值只控制展示结论强度，不代表统计显著性。各模型自身样本均分用于单模型观察，不据此默认推荐“最佳模型”。

不同模型与同模型不同服务端点分别标识；端点评分不提前合并。旧批次没有端点记录时无法确认端点一致性。单模型摘要按每个任务最新有效评分观察，完整证据仍可逐条查看。

计划任务、回答成功、回答失败、评分成功、评分失败和未完成任务分别统计。回答成功率以计划任务为分母；评分成功率以已尝试并返回终态的评分为分母。评分失败不会计作被测模型回答失败。运行统计显示全部所选运行；质量比较仅使用兼容版本组。

## 无密钥公开展示与完整历史快照

默认结论页先说明项目用途和样本范围，随后展示共同样本结果、运行覆盖、模型观察及代表性错误证据。可以在“查看全部评测记录”中查看任意正式评分的原始回答、运行时任务/标准、配置和版本、结构化依据及原始裁判响应。

仓库当前没有可供公开展示的真实运行记录。`data/` 中示例评分和 `data/demo_exports/` 文件不是真实模型实验，不能作为项目成果导入。没有真实结果时显示空状态。

在有真实运行的环境中点击 **导出完整评测快照**，得到 `evaluation_snapshot.json`。它包含运行元数据、原任务与标准（如已保存）、模型回答、全部评分状态、原始裁判响应、两类队列及请求尝试。**加载完整评测快照 JSON → 只读加载快照** 可在无API Key环境回放，无数据库写入、无模型调用；可选择历史批次或当前兼容比较组。旧版评分导入/导出仍保留，但不能独立搬运回答或原始题目。

公开部署时，可将已经检查过的真实导出文件放入 `public/evaluation_snapshot.json`，程序会自动只读加载。不要提交运行数据库或密钥。导出使用字段白名单并过滤常见密钥格式、认证字段和本机路径；发布前应自行核对业务文本是否已脱敏，程序不能自动判定所有业务敏感信息。文件中的真实来源声明无法被程序独立认证，结构校验和哈希不等于第三方真实性认证。

## 独立裁判自测

结论页的 **裁判模型自测** 可手动触发9次裁判请求（每次输出上限3072 Token，不重试）：FD-002财务、LD-001法律、CM-001投行，各有完整正确、单处重大错误、简短正确回答。固定回答在 `app/services/judge_selftest_cases.json`，明确标注为人工构造的评分器测试数据；不调用被测模型，不写正式评分表，与正式结论隔离。

检查是否识别预设错误并引用错误原文、专业准确性是否降低、重大错误是否至少降低10分、简短正确回答是否低于完整正确回答超过10分。分差是透明的观察阈值，不要求精确预设分数；不符合预期会显示原因。结果保存在会话中，可单独导出JSON。少量固定测试通过不能证明评分体系全面可靠。应用启动、浏览和普通单元测试均不会触发此调用。

## 请求用量与API费用观察

每次回答/裁判请求独立记录：模型、服务商、请求UTC时间、耗时、输入/输出Token、状态、错误类型、尝试序号及生成参数。请求前先保存运行中记录，返回后更新；中断且未收到响应的尝试用量标为未知。完整结果持久化也保存每次尝试，避免只保留最终成功响应。

“全部请求尝试、Token用量与费用估算”展示重试累计、两类请求超时及用量缺失。可上传价格JSON数组，每项必须包含：

| 字段 | 含义 |
| --- | --- |
| `provider`, `model_id` | 服务商与适用模型，必须精确匹配请求记录 |
| `currency`, `source` | 币种及可追溯的价格来源 |
| `effective_from`, `effective_until` | ISO日期，包含生效日、不包含失效日，按请求UTC日期匹配 |
| `input_per_million`, `output_per_million` | 每百万输入/输出Token单价，可为十进制字符串 |

不提供固定默认价格；同模型价格有效期不得重叠。回答费用与裁判费用分开列示，失败重试也纳入。用量或价格未知、历史尝试缺失、运行中断或币种不一致时，完整费用保持未知；仅列已知部分，不当作全部费用。只有覆盖完整、币种一致且有正式评分达标任务（沿用60分门槛）时，计算全部已记录API调用费用/达标任务数。估算不是服务商结算账单或模型公司内部推理成本。
