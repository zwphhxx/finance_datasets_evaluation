# 财务/法律/投行场景大模型对比评测

## 项目定位

本项目是面向财务、法律、投行专业任务的大模型评测原型。它不是通用 Chatbot，也不做脱离样本范围的泛化模型排名；核心是用脱敏专业样本、专业标准答案、评分标准、模型回答和 AI 评分，观察模型在当前样本范围内的回答质量、主要问题和使用边界。

项目不包含真实公司、真实交易或真实个人数据。当前结论只服务于样本内观察，不替代专业判断，也不构成模型整体能力或采购建议。

## 核心能力

- 脱敏专业任务样本库：维护任务题、业务背景、专业场景和测试状态。
- 专业标准答案与必须覆盖点：为 AI 评分提供稳定依据。
- 输入隔离：被测模型只看到任务题、业务背景和输出要求，不看到专业标准答案、必须覆盖点、不可接受错误或评分标准。
- 多模型回答对比：按样本和模型生成回答，保留成功、失败、重试和技术明细。
- AI 评分：保留五维权重，逐要点评价、匹配回答原文引文、核查固定算式并保存原始裁判响应；引文匹配不验证专业判断。
- AI 评测结论：成功 AI 评分直接形成样本内结论；跨模型质量只在兼容版本的共同有效任务上比较。
- 公开回放：完整快照只读加载，无 API Key 可查看真实历史；没有真实记录则明确显示空状态。
- 裁判自测及成本：手动9次裁判自测与正式结果隔离；全部请求尝试留痕，未知用量不记为0。

## 主流程

1. **评测结果**：比较相同任务范围中的AI评分，查看有原始反馈支持的案例。
2. **案例分析**：从对应模型、服务配置、批次及评分记录，追溯原始回答和评价依据。
3. **评测方法**：了解专业样本设计、输入隔离及结果的使用边界。

## 当前样本集

当前版本保留 13 条脱敏专业任务样本：

- 财务场景：`FD-001` 至 `FD-005`，共 5 条；
- 法律场景：`LD-001` 至 `LD-004`，共 4 条；
- 投行场景：`CM-001` 至 `CM-004`，共 4 条。

样本来源为 `data/professional_samples_13.csv`。详细字段、数据结构和 SQLite / 文件映射见 `docs/dataset_schema.md`。

## 评测边界

- 样本为脱敏抽象任务，不包含真实公司、真实交易、真实个人或敏感数据。
- 被测模型不看到专业标准答案、必须覆盖点、不可接受错误或评分标准。
- AI 评分完成后直接形成评测结论。
- 结论基于当前样本、模型回答和 AI 评分生成；仅纳入正式评分，失败评分不进入评测结论。
- 结论只代表当前样本范围，不代表模型整体能力或采购建议。
- 实时模型调用依赖外部服务，不能保证每次都成功。

## 本地运行

建议使用 Python 3.11 或以上版本。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

如需使用自定义数据目录：

```bash
export FINDUEVAL_DATA_DIR=/path/to/data
streamlit run app.py
```

## 模型服务配置

可参考 `.env.example` 或 Streamlit Secrets 配置：

| 配置项 | 说明 |
| --- | --- |
| `FINDUEVAL_MODE` | 服务端环境变量；默认 `public` 只读，`admin` 仅用于本地或具有独立访问控制的部署。不是访客登录认证。 |
| `SILICONFLOW_API_KEY` | 硅基流动模型服务 API Key；不要提交真实 Key。 |
| `SILICONFLOW_TIMEOUT_SECONDS` | 请求超时秒数；示例值为 `180`。 |
| `FINDUEVAL_EVAL_MAX_TOKENS` | 被测模型回答输出 token 上限。 |
| `FINDUEVAL_EVAL_TEMPERATURE` | 被测模型回答随机性；裁判评分固定为 `0.0`。 |

公开部署始终保持默认只读模式：即使存在API Key，也拒绝模型调用、管理页面、导入及数据写入；不初始化或迁移数据库。查询参数和页面状态不能开启管理。管理功能保留原代码，可在本地以 `FINDUEVAL_MODE=admin streamlit run app.py` 启用；独立管理部署须在应用外实施访问控制，不能将admin部署公开。管理员环境未配置Key时开始评测按钮保持禁用；发起评测需要真实模型密钥。

## 运行与恢复

点击一次“开始评测”，系统会依次生成模型回答并自动评分。每条已完成的模型回答和评分都会增量保存到数据库；外部模型服务可能受网络、限流、模型响应时间和输出长度影响。评测中断后，由用户点击“继续评测”恢复剩余任务。

数据库不可用时禁用开始与继续评测，不会调用模型服务。完整快照包含题目、回答、评分、状态、配置与请求尝试；只读加载不调用API、不写数据库。评分导出 / 导入只导入评分行；目标环境已存在相同运行批次、样本和模型的正式回答及批次记录才可纳入，并校验整数范围、总分与证据。

仓库没有提交真实运行快照，结果种子文件为空。已配置的历史结果库中有65条正式评分、覆盖13任务及5个模型/服务配置；另有39条mock裁判评分，按现有规则排除。正式历史缺少运行时任务正文、专业标准及结构化引文，不能称为完整证据，也不能用当前题库补造。公开部署可只读访问已有授权结果库；未配置或无法读取时显示空状态或不可用提示，仍能查看当前专业任务。当前没有 `public/evaluation_snapshot.json`；经来源、脱敏及公开范围核对后，才可放入已批准的快照。上传声明未经独立认证，自测答案和示例评分不是实测结果。

裁判输出格式/服务错误最多重试2次；普通浏览和单元测试不产生模型API费用，独立裁判自测须点击标注费用的按钮。确定性公式当前仅覆盖原始 FD-001、FD-002、CM-001，材料变化时不应用旧公式。

如需重新生成最终 13 条样本对应的数据文件，可执行：

```bash
PYTHONPATH=. python scripts/replace_samples.py \
  --csv data/professional_samples_13.csv \
  --data-dir data \
  --skip-db
```

本地 SQLite 数据库属于运行期产物，不应提交到 Git。

## Streamlit 部署

1. 将仓库推送到 GitHub。
2. 在 Streamlit Community Cloud 选择该仓库。
3. 设置主文件为 `app.py`。
4. 确认依赖来自 `requirements.txt`。
5. 公开部署不启用admin模式、不需要模型密钥。真实评测只在本地或受独立访问控制的管理部署配置密钥；生产结果库宜另配置仅有SELECT权限的数据库账户。
